## 当前实现

`common-mq/reliable` 提供严格消息规范化与完整性摘要、JDBC Outbox、有限批次领取、持久化退避和租约过期恢复。所有者与事件 ID 组成主键，业务去重键在所有者内唯一；业务写入必须加入现有事务。发送发生在领取事务提交之后，完成和失败更新均核对租约 token。

领取使用两个有索引的短 READ_COMMITTED 事务扫描，分别处理过期与就绪消息，避免 MySQL 的 filesort 扩大行锁范围。执行器先接纳控制任务，再在实际运行线程内领取消息；排队超时和关闭不会消耗尚未发送消息的尝试次数。投递超时后的在途发送仍可能重复，后续 Inbox/业务幂等负责正确效果。

消息载荷使用 LONGTEXT，应用严格校验 JSON、重复键、非有限数及孤立 Unicode surrogate，并重新校验摘要；保留任意精度十进制，未使用范围更窄的 MySQL JSON_VALID 约束。摘要绑定源、目标、类型、版本和规范载荷，不提供生产者身份认证。

没有新增自动装配或轮询 Bean，当前业务仍使用阶段一回写链。运行切换须与 2C 可靠提交和接收器一次完成。

## 生命周期事件契约

`workflow-api/event` 已集成 StartRequested、Started、StartRejected、Completed 四类不可变 payload、actor 快照和严格固定类型 codec。保留原提交 requestHash，Completed 不依赖独立 HTTP 终结命令；所有者、模型、表、业务关联、序号及版本在构造/解码时校验。类型不由外部 Java 类名决定。codecs 不承担来源认证，后续 handler 必须核对运输头和本地持久命令。

规格和独立质量审查通过。隔离 API 测试两 Profile 各 32 项（新增 5 组事件测试）；独立探针验证 66 项非法输入拒绝和合法长整数、补充字符、纳秒时间与稳定字节。集成后主工作区又运行两 Profile 各 5 项事件契约定向测试，零失败、错误、跳过。实现中曾观察到类型缺失及未知错误码回归失败，未保存 RED 日志；GREEN 日志及源码测试在本地/仓库分别保留。

2026-09-21 领域接入补充：实际 DurableMessage 规范化会把末尾为零的整数编码成指数形式，原 codec 的整数节点类型检查误拒绝这些合法 ID。已观察新增回归失败，改为精确十进制 `longValueExact()`，同时保留 Integer 范围检查；不改变已持久事件字节/摘要规则。测试覆盖接近 Long 上界的整数、actor/approver/round/sequence 指数，以及真实小数和 Long/Integer 溢出。两 Profile 各 7 项定向测试通过，独立审查通过；源码及回归已集成。领域模块的真实传输往返仍在接入验证中。

## Inbox 与本地投递集成证据

接收登记、领取和业务处理采用独立短事务边界；只有业务/后续 Outbox 与 PROCESSED/IGNORED 原子提交才代表成功。处理前锁定行并使用锁取得后的数据库 UTC 检查租约；失败回滚后另存有界重试证据。本地投递仅在目标处理提交后返回成功，错误目标/来源/版本在重放前仍检查。

独立质量审查发现“清理耗尽尝试的首条消息后停止扫描”的问题，已用两项失败回归复现并修复。恢复扫描将每条清理候选计入总预算（最多 20），继续寻找后续就绪消息，且在处理前一次只领取一条；不会长批次预占租约。

最终隔离测试 **55 项通过**（Outbox 29 + Inbox/本地投递 26），规格与修正后的质量复审通过。主工作区永久入口再次运行 **cloud 55 + single 55，共 110 项**，零失败、错误、跳过；日志 `bixi-reliable-inbox-integrated.log`。`make architecture-check runtime-config-check` 通过。增量迁移与主初始化表、索引在真实 MySQL 比较一致；ASCII 状态字面量的字符集 introducer 差异不改变约束。尚未装配自动 worker 或替换领域运行链。
